# App Store Connect setup (TestFlight)

One-time Apple + GitHub config so `.github/workflows/ios-release.yml` can sign and upload to TestFlight. Same secrets as Sous Kit — reuse them if you already ship that app.

## 1. Apple side

1. **Apple Developer Program** — active membership ($99/yr): https://developer.apple.com/programs/
2. **ASC API key** — [Users and Access → Integrations → App Store Connect API](https://appstoreconnect.apple.com/access/integrations/api) → **Team key**, role **Admin**.
   - Save **Key ID**, **Issuer ID**, and the `.p8` (downloadable once).
   - Admin is required for Xcode cloud signing. App Manager → `"Cloud signing permission error"`. Role can't be changed after creation.
3. **App record** — [Apps → + → New App](https://appstoreconnect.apple.com/apps): iOS, name **Jamez**, bundle ID `com.joelyoung.jamez` (register if prompted), SKU e.g. `jamez`.
4. **Team ID** — [Membership](https://developer.apple.com/account#MembershipDetailsCard) → 10-char string.

No need to create/export certs or profiles by hand — the workflow uses cloud-managed signing at export time.

## 2. GitHub secrets

**Settings → Secrets and variables → Actions → Secrets**

| Secret | From |
|---|---|
| `APPLE_TEAM_ID` | Membership → Team ID |
| `ASC_KEY_ID` | API key → Key ID |
| `ASC_ISSUER_ID` | API key → Issuer ID |
| `ASC_PRIVATE_KEY` | Full `.p8` contents (multiline OK) |

Optional **variable**: `JAMEZ_IOS_BUNDLE_ID` (default `com.joelyoung.jamez`; must match the App Store Connect app record or the TestFlight upload fails with "Cannot determine the Apple ID from Bundle ID"). Build number = `github.run_number` (set in the workflow).

## 3. Ship

- Auto: push to `main` touching `apps/mobile/**` or `packages/core/**`
- Manual: **Actions → iOS release → Run workflow**

Without the secrets, the job warns and skips (stays green). With them: IPA → TestFlight (plus a workflow artifact).

Then: TestFlight app on phone → App Store Connect → TestFlight → add yourself as internal tester → install.
